# CV tailoring rules

Use these when producing a tailored resume in Phase 5 of the career-ops
skill. The goal is honest re-framing, not rewriting a different person.

## Do

- Reorder bullets/experience so the most relevant-to-this-posting items lead.
- Mirror the posting's own terms for skills the user genuinely has (e.g. if
  the user's resume says "K8s" and the posting says "Kubernetes", write
  "Kubernetes").
- Quantify impact wherever the base resume has numbers to draw on
  (%, $, time saved, scale).
- Tighten the summary/headline line to name the target role and the one or
  two qualifications most relevant to it.
- Keep it to the same length as the base resume (typically one page unless
  the base resume is longer for a good reason).
- Use plain, single-column formatting: no tables, text boxes, icons, or
  multi-column layouts that break ATS parsing.
- Keep the file name pattern `career-ops/cv/tailored/<company>-<role-slug>.md`.

## Don't

- Don't add tools, titles, employers, dates, degrees, or metrics that aren't
  in `career-ops/cv/base-resume.md`.
- Don't change job titles or dates to sound more senior.
- Don't invent a certification, language, or clearance the user doesn't have.
- Don't remove context that changes the meaning of an accomplishment just to
  fit more keywords in.
- Don't stuff invisible/white-text keywords for ATS gaming — it doesn't work
  reliably and reads as dishonest if a human ever inspects the file.

## When there's a real gap

If Phase 3's requirements-match (section B) found a genuine gap between the
posting and the base resume, don't paper over it. Either:
- Reframe adjacent real experience honestly ("built X" → "designed data
  pipelines that fed X" if that's what actually happened), or
- Leave it out and let the cover letter / conversation address it, or
- Flag it back to the user before tailoring if the gap is large enough that
  applying may not be worthwhile.
